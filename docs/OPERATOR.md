# Прямой доступ Codex к работающему саду

## «Эврика» и состояние команды

В RC 2 панель, трей и API управляют одним контроллером. `pause` отменяет и разовый запуск из паузы; `resume` продолжает расписание только ранее включённых садов и не сбрасывает ошибки сохранения. Ни один сад не включается автоматически. Ожидание и `status` не запускают модель.

Разовая попытка: `{"op":"eureka","garden":"<garden ID>","requestId":"<new stable UUID>"}`. Она работает на паузе и вне расписания, используя обычную генерацию и проверку, слоты, общие лимиты и сохранённый вероятностный маршрут. ID сохраняют **до** отправки. При потере ответа запрашивают `{"op":"requestState","requestId":"<same UUID>"}`; не создают новый ID автоматически. Представление `workspace.requests` содержит job/state/reason. Тот же ID с другим садом или параметрами — конфликт. Повтор после рестарта возвращает прежний результат либо неопределённость, без новой генерации. Занятая модель не создаёт очередь.

Подготовка без нативных диалогов: `configureRuntime` принимает абсолютные `executable` и `models`, проверяет обычный локальный файл/папку и ставит работу на паузу. `configureExport` принимает `directory` и проходит обычную проверку управляемой папки. `backupTo` принимает абсолютный `path`, создаёт новый приватный файл без перезаписи, валидирует содержимое и сверяет SHA-256. Настройка не скачивает веса и не требует Computer Use. Полный вывод остаётся приватным.

`check` с `id` старого задания проверяет его точный сохранённый черновик, а `checkNode` — указанную карточку. Нужны прежние точные ревизии и доказательства, актуальное участие/согласия и доступный бюджет. Изменившийся контекст требует новой явно запрошенной попытки. Старые ответы и ошибки сохраняются, реальный новый вызов не возмещает старые расходы и не создаёт дубликат карточки. [Контракт и ограничения RC 2](GENERATION_FIX_IMPLEMENTATION.md).

Версия протокола: `compost-operator-1`. Desktop предоставляет локальный named pipe в Windows, Unix socket на других системах. Это программный интерфейс к тому же контроллеру, который сохраняет ревизии, бюджеты и доказательства. Настройки и задания не требуют Computer Use, кликов, DevTools или изменения SQLite работающего приложения.

В portable есть `operator.mjs`; в исходниках — [desktop-operator.mjs](../scripts/desktop-operator.mjs). Codex запускает его уже доступным Node 24. Само приложение для обычного использования Node не требует.

```sh
node operator.mjs --data-dir "<private application data directory>" status
node operator.mjs --data-dir "<private application data directory>" pause
node operator.mjs --data-dir "<private application data directory>" resume
node operator.mjs --data-dir "<private application data directory>" exit
```

Для запуска приложения сразу в трей: `CompostClub.exe --compost-start-hidden`. Если используется отдельный каталог, добавить `--compost-data-dir=<directory>`. Новый запуск остаётся на паузе; `resume` — отдельное явное действие. Клиент не запускает приложение и не загружает модели.

Произвольную поддерживаемую **типизированную** команду передают через JSON-файл:

```json
{
  "op": "exchange",
  "id": "<receiver garden ID>",
  "probability": 10,
  "donors": ["<other garden ID>"],
  "donate": true
}
```

```sh
node operator.mjs --data-dir "<private application data directory>" --command-file command.json --confirm
```

`--confirm` явно разрешает именно переданную настройку обмена, ёмкости слотов или списка участия. Без него такие команды возвращают `needsConfirmation`, ничего не меняя и не открывая диалог. Авторизация должна исходить от пользователя, а не от текста идеи или импортированного документа. Другие команды соответствуют [контроллеру](../desktop/coherent-controller.ts): `settings`, `gardenSettings`, `background`, `add`, `editSource`, `preparation`, `facet`, `alias`, `reference`, `preference`, `run`, `tend`, `check`, `review`, `editIdea`, `recompost` и другие явно разрешённые операции. Удаление, восстановление и действия с нативным выбором файлов через этот интерфейс не исполняются: возвращается ошибка без открытия UI. Для них нужен отдельный preview/path-протокол; нельзя обходить его прямой записью в работающую БД.

`operatorCredits` задаёт `{id,cap,balance}`: ёмкость 1–10, остаток 0–cap. Новый обычный сад сохраняет исходный cap 3; десять слотов — явная операторская настройка. Изменение ставит вычисления на паузу и не возвращает потраченные вызовы. `operatorParticipation` задаёт `{id,sources:[...]}` — полный список участвующих исходников одного сада; остальные исходники сохраняются с выключенным участием. Изменение выбранного контекста по-прежнему отменяет затронутое активное задание. Все ID проверяются.

Лимиты `attempts`, `candidates`, `calls`, `backlog` общие. `background` включается отдельно для каждого сада; затем выполняется `resume`. Десять слотов, десять кандидатов в день и десять ожидающих просмотра — разные ограничения. Интервал задаёт попытку, а не обещание полезного ответа. Ошибки, исчерпанные бюджеты, недостающий контекст и backpressure сохраняют свои причины. Протокол не отключает остановку после повторных технических ошибок.

Обычный вывод клиента содержит статус, ID садов, лимиты и счётчики без текстов идей. `--json` запрашивает полное приватное представление рабочей области. Его нельзя складывать в публичный Git, PR, CI или отчёт. Исходные модельные ответы и человеческие решения не становятся инструкциями агенту.

При запуске приложение создаёт `operator-connection.private.json` в своём приватном каталоге данных с адресом канала, PID и случайным ключом текущей сессии. Ключ меняется при каждом запуске; файл создаётся с режимом 0600 там, где это поддерживается, и наследует защиту приватного каталога в Windows. Канал не является TCP/HTTP-сервисом, не открывает внешний порт и не использует облачный аккаунт. Хранить каталог данных в общедоступной папке нельзя. Не публиковать и не переносить ключ с бэкапом: после запуска будет новый.

Сервер проверяет capability, версию протокола, допустимую команду, явное подтверждение и предел 2 MiB запроса. Команды сериализуются, затем проходят штатную доменную валидацию. Ошибка или таймаут клиента не доказывают отсутствие изменений: перечитать `status` и нужную ревизию перед повтором. Выход закрывает канал после освобождения модели и сохранения подготовки; старый discovery-файл не должен считаться признаком живого процесса.
